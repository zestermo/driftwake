# tools/dev

Headless tests, co-op tests and screenshot/render tools for Driftwake. All are
`extends SceneTree` scripts run with `--script res://tools/dev/<name>.gd`. See CLAUDE.md at the repo
root for how to run them on Windows. Output goes to `tools/dev/out/` (gitignored, has a `.gdignore`
so Godot does not import the PNGs).

## Checks

- `run_tests.ps1`: The test runner: compile check, then the named tests (suites, atomic tests `t/<group>/<name>` or a whole `t/<group>`; or every test, or `-Changed [-Base ref]`), 5 at a time (`-Jobs`); a test stops at its first FAIL or script error and prints it whole, with the seed it ran on and the line to rerun it (`-Seed N`: that seed instead of the suite's own, passed as env `DRIFTWAKE_SEED`; never cached or shared). Each pass records every project file the run loaded (`.git/crew/deps/<test>.txt`) and is cached under the hash of those files' contents, so it stays good while they don't change, whatever else does (`-Force` reruns; `-Exact` caches by the whole tree instead, for land's smoketest); `-Light` leaves out heavy.txt and co-op. Logs in `out/logs/<test>.log`.
- `scripts/game/dep_record.gd`: what a test run loaded. Settings starts it when `DRIFTWAKE_DEPS_OUT` names a file (the runners set it per Godot): a resource loader first in line that claims nothing sees every load, and at exit (Settings' `_exit_tree`, the last autoload out) the files still cached are added and the list is written. `preload("res://scripts/game/dep_record.gd").note_dep(path)` adds a file read without the loader or a folder that's listed (`.../`: its file names count): dialogue JSON, ItemDB's items folder.
- `test_kit.gd`: Shared by the suites (`const TK = preload(...)`, or `load(...)` in a one-line `_initialize`): `seed_of(self[, fixed])` picks the suite's seed (DRIFTWAKE_SEED or its own, default 4242), seeds the global rng and GameManager.chain_seed and prints `SEED n`; `seeds_of(list)` for suites that loop over seeds (just -Seed's when given); `use_seed(self, s)` before each; `wait_ticks(n)` / `wait_secs(s)` give a physics tick to wait for and `ticking(until)` says whether to keep waiting (frames and process seconds stretch under load, ticks are game time).
- `compilecheck`: Compiles every project script (or just the ones named) with the autoloads loaded (Godot's own `--check-only` doesn't know Net, FX...) and prints `COMPILE OK (n scripts)` or `COMPILE FAILED <path>` under Godot's errors. Exit code = failures. `run_tests.ps1` runs it first (~6 s) and runs no suites if anything is broken (`-NoCompileCheck` skips it). Also the wall-clock lint: a `Time.get_ticks_*`, unix or system time call in scripts/ or scenes/ fails as `WALL CLOCK <path>:<line>` unless `wallclock_allow.txt` lists it (the edit hook, run_tests, finish and land all see it; a full run also names allow-list entries that match nothing now). Args: [paths...]
- `wallclock_allow.txt`: the wall-clock calls game code may make (`path` or `path:function` | why it needs real time): the co-op session clock, saves' dates, music's resume timer, build timing and budgets, menu debounces, dev capture, the perf log.
- `affected.ps1`: which tests what changed can affect (uncommitted files, or `-Base main` for a whole branch), by each test's recorded loads (a file in a listed folder, or a source's `.import`, counts): an atomic test whose loads include a changed file; a suite or co-op mode when a changed file it loads is test-side (`tools/dev/`) or one test_map says it's about (every suite loads the whole game; `-Wide`: any changed file it loads). A test with nothing recorded yet falls back to `test_map.txt`; an atomic test or a suite no map line names is picked until its first pass. `-Explain` says why each was picked. `run_tests.ps1 -Changed [-Base ref]` runs them and says which co-op modes to run (nettest.ps1 [mode]).
- `test_map.txt`: the hand-kept map: what each suite is about (affected.ps1 narrows a suite's loads by it), and the picker for tests with nothing recorded yet.
- `land.ps1`: Lands a finished parallel session's worktree branch on main (run in a worktree with no branch: that worktree's own): rebase onto main, compile, smoketest (always, keyed by the exact tree so never carried over the rebase), then the tests whose loads the branch changed, minus heavy and co-op (`-NoTests`: compile and smoketest only; a pass on the same contents of what a test loads carries over the rebase by itself), fast-forward main; never pushes, prints one line. One landing at a time machine-wide (`.git/crew/landing.lock` + `landing.json`, waiters in `landq/`, in order; a second lander says whom it waits for). A branch that already has main in it (merged in) isn't rebased, so it fast-forwards; one with merge commits of its own gets main merged in instead of a rebase. If main moves during the tests, its new commits are taken in the same way: docs/, *.md, web/site/ and files no test's recorded loads include go straight on to the fast-forward, anything else re-runs the compile check and only the tests (and smoketest) whose loads it changed (5 moves in one landing: it gives up). A conflict stops a self-landing mid-rebase or mid-merge (from elsewhere it backs out) and prints the steps. Refuses when the main checkout has uncommitted changes in files the landing touches, or a test run is going in the worktree; commits stray untracked `.uid` files of the branch's scripts, deletes the main checkout's untracked generated copy of one it brings. `-List` shows every worktree, how far ahead it is and who's landing. Before rebasing it lists other sessions changing the same files; landing releases the branch's claim. See CLAUDE.md "Parallel sessions". Args: [branch] [-Onto main] [-NoTests] [-Remove] [-List] (`-Light` accepted and ignored)
- `unwork.ps1`: Removes a landed worktree's folder (through a `\\?\` long path: `git worktree remove` fails on Windows with "Filename too long" in `.godot`) and deletes its branch and claim. Refuses with commits main doesn't have or uncommitted changes unless `-Force`; run it from the main checkout once the session is closed. Args: <name | worktree-name> [-Onto main] [-Force]
- `suite_times.ps1`: Each suite's median time from passed runs, slowest first: total, setup (to its first PASS/FAIL line: Godot, loading, the world build) and checks, plus a full run's machine time. Reads `.git/crew/ledger/history/<suite>.jsonl` (every result: run_tests/nettest's Write-Ledger), the day of live runs before the history began, and each suite's last result. Args: [-Top n]
- `crew.ps1` + `crew_lib.ps1`: the parallel sessions' board (each worktree's claim and the files it's changing, test slots in use), `claim "task" -Areas ...` / `release` / `overlap`; `-Hook` is the SessionStart hook's form. The lib (state in `.git/crew`, shared by every worktree) gives run_tests/nettest their machine-wide test slots (`DRIFTWAKE_TEST_SLOTS`, default 5), each test's recorded loads (`deps/`) and the cache of passes by those loads' contents (`Get-TestKey`; the tree before anything's recorded; skipped unless `-Force`). `hooks/crewcheck.ps1`: after an edit, tells Claude if another session is changing or has claimed that file.
- `hooks/mainmoved.ps1`: dot-sourced by guard.ps1 (before each Bash/PowerShell command) and crewcheck.ps1 (after each edit): in a worktree branch, says once per new main head that main moved (the commits' subjects) and to commit, `git merge main`, fix conflicts and rerun the covering tests at the next clean point. Never acts by itself; quiet when main is already in the branch. The quiet path reads a few small files, no git (~10 ms; main's last-seen head per branch in `.git/crew/mainseen/`).
- `suites.txt`: every suite run_tests.ps1 runs, one per line (merges by union).
- `suite_groups.txt`: the Tests pane's themed groups ("Group: suite suite ..."; a suite on no line shows under Other; merges by union). Atomic tests get a group per `t/<group>` folder by themselves.
- `test_status.ps1`: every test's state against this checkout's code: up to date (passed with the current contents of everything it loads; before its loads are recorded, on this code or older code nothing since touches per test_map.txt), needs to run (lists the files it loads that changed), failing (last run failed, nothing it loads changed since), never run. Reads `.git/crew/results`, `deps/` and `ledger/` (each test's last result, written by run_tests/nettest), writes `.git/crew/status.json` for the Tests pane (with `landing`: who's landing now and who's waiting). `-Stale` prints just the names to run (stale, failing or never run).
- `run_needed.ps1`: runs every test test_status calls stale, failing or never run (run_tests, then nettest per co-op mode). The Tests pane's "Run needed" starts it in its own minimised window; `-List` just prints what it would run.
- `heavy.txt`: the slow whole-world suites `run_tests -Light` (and so land.ps1) leaves out; prepush.ps1 runs them.
- `prepush.ps1`: the gate before a push: run_needed.ps1 (every stale, failing or never-run test, heavy ones, atomic tests and co-op modes included), then pushes if test_status has nothing left. `-CI`: GitHub runs everything instead (ci.ps1), a green run pushes that same commit and deletes its ci/ branch (a red one keeps it for `gh run rerun --failed`). `-NoPush` just runs it. `-Release` (before tagging a version): perf_gate.ps1 must pass too, after the tests.
- `ci.ps1`: every suite and co-op mode on GitHub for HEAD's commit: pushes it to `origin ci/<branch>` (never main; `ci/<short sha>` when detached), waits for that commit's Tests run (one `gh run watch`), prints each job's verdict and exits 0/1. Uncommitted changes aren't tested.
- `.github/workflows/tests.yml`: the Tests workflow (pushes to any branch but main, and by hand): a plan job imports once (the `.godot` cache) and deals the suites into jobs (ci_plan.ps1), a job per shard runs `run_tests.ps1 -CI`, one per co-op mode (default, chain, board) runs `nettest.ps1 -CI`, a verdict job fails the run if anything failed. Each job's summary has a table (suite, time, result, the failure block) and its logs are an artifact.
- `ci_plan.ps1` + `suite_times.txt`: the Tests workflow's matrix: each heavy.txt suite in its own job, the rest dealt longest-first over `-Shards` jobs (11) by the rough seconds in suite_times.txt (a suite not listed counts as 60), and every atomic test (`t`) in one job.
- `ci_lib.ps1`: run_tests/nettest `-CI`'s side (an in-memory run, the job summary's table and error annotations) and the ci/ branch name. `-CI` skips the crew (slots, pass cache, in-flight sharing, ledger, live runs) and the import (the workflow does it); the judging (FAIL lines, SCRIPT ERROR, RESULT, stall/flood limits, flaky.txt's retry) is crew_lib's, the same as locally.
- `flaky.txt`: known flaky checks ("suite | FAIL text"; nettest's suite is "net"). A failure made only of these is retried once by run_tests/nettest.
- Live runs: run_tests.ps1 and nettest.ps1 stream each Godot's output to its log as it runs (cmd's redirect) and write `.git/crew/live/<run>.json` (suites, state, seconds, last lines, why it failed). The **Tests** pane (`/tests`, a Claude Code mod) shows them. They stop a suite that stalls (`DRIFTWAKE_TEST_STALL`, default 150 s quiet), can't parse its scripts, floods script errors or passes 25 MB of log. A suite another runner is running on the same dependencies is waited for, not run twice (`.git/crew/inflight`).
- `build_web.ps1`: The browser build: checks the web export templates (prints the download if missing), exports preset "Web" (thread-less, Compatibility) to `web/build`, copies it into the site as `web/site/play`, prints file sizes (raw and gzipped) and flags any over Cloudflare Pages' 25 MiB. Args: [-DebugBuild]. See docs/web_build.md.
- `site_gifs.ps1`: The site's GIFs: encodes siteshot's clip frames with ffmpeg (one palette per clip, no extra dither) into `web/site/img/clips/<name>.gif` plus a poster `<name>.jpg`, and prints the sizes (keep each under ~3 MB). Args: [-Out tools/dev/out/site] [-Fps 15] [-Colors 256] [-Only name,name]
- `serve_web.ps1`: Serves `web/site` on http://localhost:8060/ (the game at /play/) to try the browser build. Args: [-Port n] [-Threads: adds COOP/COEP for a threaded export]
- `hooks/guard.ps1`: Claude Code hook (PreToolUse on Bash/PowerShell): refuses a suite run straight through Godot and `git add -A` / `git add .` in the main checkout; answers "allow" (no permission prompt, whatever the mode) for a command made only of the runners and tools (run_tests, nettest, test_status, affected, run_needed, suite_times, crew, land, bench, bench_compare, perf_gate; Godot with `--script res://tools/dev/<tool>.gd`; `py tools/texture_gen/<gen>.py`), each optionally piped into readers (Select-Object, Select-String, Sort-Object, Measure-Object, Format-*, Out-String, head, tail, grep, wc). A redirect, `$(...)`, a backtick, a script block or anything else asks as usual; prepush, ci and unwork always ask. Then mainmoved.ps1's note.
- `hooks/gdcheck.ps1`: Claude Code hook (`.claude/settings.json`, PostToolUse on Edit/Write): after Claude edits a .gd file it compiles that file (~2 s) and hands any errors straight back to Claude.

## Atomic tests on the stage (tools/dev/t/)

One behaviour each, in its own process, on the light test stage instead of the generated world (~11 s each, of
which ~8 s is Godot compiling the project's scripts at boot; the stage itself is up in ~2 s). Run one by path or a
whole group: `run_tests.ps1 t/player/dodge`, `run_tests.ps1 t/player`, `run_tests.ps1 t` (logs as `t.player.dodge.log`).

## Test suites (run_tests.ps1)

Each prints `PASS ...` / `FAIL ...` lines and a final `RESULT OK` / `RESULT fails=0` / `RESULT FAILED (n)`.

- `chartest`: Character builder: every option + random looks build, apply_look keeps weapons, legacy looks convert.
- `invtest`: Gear / paper doll / character sheet / abilities.
- `ragtest`: Player ragdoll: knockdown -> get up, death -> stays down -> respawn.
- `bugtest`: Scuttlebugs: spawned in the jungle, notice -> rear -> ram, hitstun, knockdown, death + gold.
- `storytest`: The story: off outside a new game; begin() locks the ship and the skill map; waking on the beach (lying, the gull lands, caws and flies off, standing, the objective on the HUD and its marker); Grell's den hidden from the wake spot and Pell, the marker to its climb, the climb driven (slabs, knife edge, gap, rope ladder) and the sea hoist's ladder; each talk step starts at the NPC's story line and moves on (Tackett busy before his turn); the smugglers, Grell, the queen and Morrow count when beaten near you; Vey's free point opens the skill map, Tackett's keel gives you the ship; the end; restored mid-story.
- `foresttest`: Brinehollow's west: the bigger island, the pirate den (crew, Captain Grell's overhead name and bar, strongbox, sloop), canopy spitters (drop, spit poison, fall, climb back), the brood cave (the queen wakes, boss bar, stagger, brood, slam, venom fan, reset, death, hoard) and the Queen's Fang.
- `denpathtest`: Grell's cliff path: the sea ladder pulled up until a captain stands on the top (then let down, saved, in the world state), Grell waits while his crew fights until a captain is at the fire, the cave (small bugs, the brute: several hits, no boss bar, spitters, dripstone), every gap driven with the real jump (run or sprint as it asks, the longest with a run and the double jump, headroom over each), a walk off into the sea and the swim back to the beach, the bridge chain (F at the lip, caught mid-jump), the story marker.
- `shiptest`: Ship: gentle swell, helm (visible captain), sails set in steps that stay set (furled canvas rolls down), turning, riding the deck, keeps sailing with nobody at the wheel, shore collision.
- `swimtest`: Swimming: fall in, float, swim, stamina, dive, exhaustion, ladder, ledge, wade out.
- `grunttest`: Pirate grunts: camp, alert, attack turns, guard/guard break, hitstun, parry stagger, knockdown, death, return home.
- `guntest`: Grunt firearms: rifle shots on a line (hit when standing on it, miss when dodging/sidestepping), reposition, shove, pistol swap, heavy-attack glow, wider parry window.
- `fixtest`: Plunge attack, rifleman ragdoll fix, shove knockdown, two-handed rifle.
- `watertest`: Water for grunts and ragdolls: grunts avoid the sea, swim back to shore when they end up in it, ragdolls plunge under then float, knocked-down swimmers (grunt and player) bob up and swim on, dead bodies float.
- `powertest`: Devil Fruit (Ember) + skill bar + bindings + braced ragdolls + foot IK + parry sound.
- `progtest`: Progression + skill map + fighting styles + fruit types + save/load.
- `savetest`: Title screen + save slots: new game, save, quit to title, continue, a second slot, loading from the pause menu, deleting (each load waited for until its new captain is in and the save applied, up to 60 s).
- `vinetest`: Vine Fruit round 2: energy drain, grapple points on trees, swing body alignment + loose limbs + release tilt that rights itself, arm vines, grapple pull (light enemy) and zip (heavy enemy), fists in the fist stance, punch wind FX.
- `r6test`: Round 6: skill keys after closing the map, map tabs + framing, menus fit the screen, quick items, power auras, vine dash trail, Haki look, block, red unblockable grunt heavy, fall damage.

## Co-op (nettest.ps1)

`nettest.ps1 [mode]` runs a headless host and client on localhost. Modes: none (the full session), `late` (the host
starts single player and hosts from the pause menu), `three` (plus netwatch), `hostquit`, `water`, `board`, `chain` (the
last two below), `duel` (the guest's F menu on the host's captain and Inspect from its machine, no hurting outside a duel,
challenge and accept, the countdown, the guest's blade landing lightly, the host's finishing blow downing the guest without
death, the host's win and XP, both back up with their health from before), `jam` (the host plays the fiddle, the guest
joins on the concertina: the same tune and start both ways).

- `nethost`: Co-op test, host side: hosts a world and runs the client's commands (see nettest_node.gd). In `chain` mode it first lands on the chain's first island in single player and fells its camp's captain, then hosts. Args: <port> [mode]
- `netclient`: Co-op test, client side: joins the host (nethost.gd, same port) and checks the session: puppets both ways, enemies in sync, hits each way (client hits an enemy, an enemy hits the client), gunshots, kills (coins + XP), knocked out + revive, actions mirrored, fruit claims, the helm, spawner waves, burning brush, leaving. Mode `board`: a pirate ship boards the host before the client joins, then again with the client at the helm, then her deck crew turn: the client checks the boarders and deck crew are puppets on the right deck, in the crewmen's bodies, hits both ways and a kill. `chain` mode instead (retrying the join until the host's up): joining late it has the host's chain state (seed, where the crew is, unset, since when) and builds the same island (name, place, size, sites, camp crew - the captain the host felled isn't standing - village people, chests, the beast); a chest emptied by the guest is gone for it and still there for the host (each captain loots each chest once) until the host empties its own; the host's clock running on 15 minutes sets the log pose here and the next islands are built the same; the guest landing on an island ahead moves the crew there for both (the island behind and the fork's other side go); the guest felling the beast sets the log pose for everyone; the host landing on the next island moves the guest's chain on; a guest's save keeps its own world's chain. Args: <port> <start_delay> [mode]
- `netwatch`: Co-op test, a second client: joins alongside netclient.gd and checks it sees the host AND the other client (snapshots relayed by the host). Args: <port> <start_delay>
- `nettest_node`: Co-op test helper: the same node (/root/NetTest) on the host and the client. The client sends commands, the host runs them and replies. `chain_report()` is the chain as a machine has it (state and every chain island standing), for host and guest to compare.
